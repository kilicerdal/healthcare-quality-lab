# V8.3 quick operating guide

## Start, check and stop

From the standalone project environment:

```sh
.venv/bin/python -m tools.showcase_server start
.venv/bin/python -m tools.showcase_server status
.venv/bin/python -m tools.showcase_server stop
```

The default address is `http://127.0.0.1:8902/#workbench`; state is `.local/demo-v830`. The launcher waits for readiness, resumes existing state, seeds the recorded V8.2 example once, and starts no model requests. Its log is `.local/demo-v830/showcase-server.log`. Repeated start is idempotent for a healthy owned server. Stop preserves SQLite data and requires ownership proof, so a stale PID or unrelated application is never killed. Existing shared-authentication environment settings are honored.

For a fresh checkout without dependencies, run the existing `python3 -m tools.bootstrap --runtime-only` first. The launcher does not install packages or download models automatically.

## Inspect recorded evidence first

The page automatically selects the latest recorded experiment, if present. The original interrupted V8.2 example shows seven assessed trials, seven correct API expectations, four fully valid predictions, three worksheet mismatches and thirteen not assessed. Its final accuracy is not reported because qualification is incomplete. An interrupted request is labeled outcome unknown; later unattempted rows are labeled not run.

Historical records retain their original source hashes, raw predictions and results. New view metrics do not rewrite them. Historical/interrupted predictions remain nonexportable; starting a short development run does not qualify a model.

## Explicit live inference

Expand “Optional live AI,” choose a development scenario and set a total job budget from 1–300 seconds (default 180). Click “Estimate duration” first. This does not call the model. It uses recorded completed-request medians where available and labeled conservative defaults otherwise. Changing any selection or the budget invalidates the estimate.

The estimate is not a completion guarantee. If it exceeds your budget, the job may stop before all requests finish. The budget begins at job admission; model-availability preflight is separately bounded. Per-request transport timeouts are clipped to remaining job time. The client-visible job is interrupted at the budget, unfinished rows remain in the record, and late output is fenced. Backend cancellation is best effort; already-running backend work is not guaranteed to stop instantly, and its generation lock stays held until its worker returns.

The UI polls status without additional inference. No hidden retry, automatic repair, cloud fallback or model pull occurs.

```sh
.venv/bin/python -m tools.expectations_v83 --models qwen2.5-coder:3b --tasks D83-01 --max-seconds 30 --state .local/my-v83.sqlite --output artifacts/v8.3/my-pilot.json --dry-run
```

Remove `--dry-run` only for an intentional model request. Existing output files cannot be overwritten. D83-01 is an exposed noncovered-vision worksheet case; D83-02 is an exposed mixed-line account-timing case. These are development examples, not fresh qualification inputs. The V8.3 cohort labels previously published H82 cases historical rather than reserved.

## What the worksheet guidance changes

For rejected coverage, eligible money is noncovered money, not a preliminary member charge. Required member and payer worksheet values remain zero. Remaining-cap fields always refer to balances immediately before that particular line. Earlier covered lines update accounts before the next line, including a later rejected line; rejected coverage never resets balances to policy limits.

The model still supplies every numeric value. The parser copies model-authored aliases exactly; the independent evaluator still rejects wrong worksheets. No historical failed value is repaired or relabeled correct. Prompt improvements alone do not establish improved model accuracy.

## Review and execution

A completed current-source prediction must independently match all observations and numeric worksheets before export. Export creates an unapproved proposal. Inspection, approval and actual HTTP execution remain separate. A completed one-case development run is not a completed ten-input qualification.

The report analyzer compares blind self-review only when it was requested and both stages were assessed. An unrequested review is not a regression; an unavailable requested review is not an assessed failure pair. Experiments with different total time budgets cannot be pooled into one comparable score.
