# V7.5 — Complete synthetic claim journeys

## Purpose and location

Single submissions cannot reveal errors caused by later payments, corrected lines, appeals or annual account transitions. This milestone exercises connected lifecycle behavior.

All implementation belongs to the existing standalone project at `/Users/erdalkilic/Documents/Healthcare Quality Lab`. No existing sibling project was modified and VS Code was not opened. This is a milestone in one combined V8 delivery, not a separately deployed application.

## What was built and how

### Engineering decision 1

Seven fresh-state journeys cover multi-line pricing, paid adjustment followed by reversal, appeal and resolution followed by payment, a December-to-January benefit transition, coordination with another payer, partial coverage with payment, and an identical payment replay.

### Engineering decision 2

Financial mutations include explicit reads. Complete successful observations contain payout/member/other-payer/noncovered cents, signed ledger balance and count, revision, history event count, individual/family accumulators, policy version and partial-coverage flag.

### Engineering decision 3

Each journey compiles through the independent reference and is executed against actual SQLite-backed application behavior. The year-transition journey reads both years; replay verifies that the original response does not create a second debit.

### Engineering decision 4

Partial payment here means payment of a claim with a mix of covered and noncovered lines. Installment scheduling, banking settlement, real remittances, EDI formats and real insurer coordination rules are outside this milestone.

## Code and review map

Primary implementation and evidence entry points: `healthcare_quality/coverage_packs.py: journeys; healthcare_quality/advanced_runner.py; tests/unit/test_v8_foundations.py`. Related behavior is exercised by the V8 unit/API/browser controls and the connected disposable rehearsal.

## Why these choices

The implementation extends the existing DSL, independent reference, persistence and review gates instead of creating another incompatible framework. It keeps deterministic engineering checks usable without a model and retains original AI outputs. Explicit authorship, source fingerprints and separate review prevent a successful job or attractive screen from being mistaken for a correct model answer.

## Problems found and corrected

Initial validation exposed a Flask endpoint naming collision, a missing schema definition in the reference-peer endpoint, a missing route parameter, and the report route's missing/new heading contract. These were corrected rather than bypassing tests. The first Mac Firefox attempt could not launch its profile; Linux executed the complete Firefox suite. A recording selector failed on an icon-prefixed accessible name and was replaced by a stable navigation selector, with a workbench round-trip browser assertion. Final review also added duplicate-aware AI export, safe inspection of invalid saved proposals, symlink evidence rejection and one source fingerprint calculation per queue view.
