This is one standalone synthetic lab. V6.3–V6.7 are implementation milestones in the combined release; the older framework, reports and proof page remain available.

## Run a fresh isolated copy

```sh
python3 -m tools.launch_demo --state-dir .local/demo-v67-fresh --port 8897
```

Open `http://127.0.0.1:8897/#research`. Use a new directory and unused port. The launcher does not reset another project or existing state, call a model, download a model or make paid requests. Replayed measurements retain their original provenance.

## A five-minute engineering story

1. Explain the contract: an invented H1 2026 commercial PPO medical amount of 100000 cents has a 10000-cent deductible, 1000-cent copay and 80% payer share after both. A fresh payout is 71200 cents; actual member charge is 28800 cents. These are teaching facts, not coverage advice.
2. In Advanced AI test studio, load the **authored** adjustment control. Inspect independent checks and full expectations. It covers submit, pay, adjustment to a 31200-cent payout, reversal and readback. State clearly that this control is authored, not freshly AI generated.
3. Enter an inspection note, approve the snapshot and execute through HTTP. Show one case passing in fresh stores. Point out ledger balance/count, revision/event count and restored member/family accounts. Approval and execution are separate actions.
4. Inspect Advanced AI evaluation scorecard. Read raw eligibility and reference-assisted eligibility separately. Expand the original raw output, provider errors and frozen inputs. A completed experiment is not necessarily a good model answer. The first development timeout is preserved separately.
5. Run the **lost acknowledgement** external-service scenario. The synthetic peer commits before the response times out. Reconciliation finds the original receipt and leaves exactly one external payment and one local ledger entry. Then run **webhook replay** and show duplicate/stale notifications cannot create extra money.
6. Open the linked GitHub Actions run and release manifest. Explain what the source fingerprint, checksum, passing reference controls and bounded mutation scores establish. A green badge does not establish real Medicare policy, production capacity or clinical correctness.

## An actual local AI request

Page load and authored controls do not invoke a model. Start installed Ollama separately, then explicitly request a proposal:

```sh
.venv/bin/python -m tools.advanced --model qwen3.5:27b \
  --requirement 'For M100 and commercial_ppo on 2026-03-01, submit a 100000-cent medical claim, pay it, then reverse it and verify ledger, history and accumulators.' \
  --output artifacts/my-advanced-proposal.json
```

Choose a fresh output filename. The request uses a bounded advanced profile and fixed loopback endpoint. The result remains unapproved. If it fails schema/oracle checks, inspect the failure; do not advertise it as a passing test. Requesting a correction is another actual local-model request, creates a separate proposal and discloses reference assistance. Scenario changes remain blocked.

## Run frozen raw/corrected measurement

```sh
.venv/bin/python -m tools.advanced_evaluate --model qwen3.5:27b \
  --tasks ADV-03 ADV-05 --repeats 2 --correct \
  --output artifacts/my-advanced-measurement.json
```

The first two cohort tasks are development, the other six reserved until exposed. Exposure is recorded before requests in `.local/advanced-evaluations-v64.sqlite`. Starting a new ledger is not proof of unseen data. Fixed-seed repeats are correlated. This command measures proposals without approving or executing them.

## Run external-boundary rehearsals

```sh
.venv/bin/python -m tools.integrations --output artifacts/my-integration-rehearsal.json
```

Nine profiles use actual loopback HTTP and disposable state: normal, lost acknowledgement, temporary unavailability, persistent timeout, wrong receipt, inactive eligibility, changed claim, actual child-process interruption recovery, and webhook replay. Outbox intent uniqueness is also tested under concurrent different keys. These integrations settle the first synthetic payment only; they do not externally reconcile every later adjustment/refund.

## Live Ollama in GitHub Actions

Use a reviewed main checkout and an already configured dedicated `colima-hql-*` Docker context. The isolated VM must reach the host Ollama service through its verified Lima bridge. Run:

```sh
.venv/bin/python -m tools.ollama_ci --context colima-hql-v62 \
  --model qwen2.5-coder:3b --cohort reserved-smoke \
  --output artifacts/my-live-runner-receipt.json
```

The tool verifies owner/main/source, enforces the total request budget, dispatches a uniquely labeled job, registers one ephemeral non-root container runner, waits for evidence, and removes the container/registration. Its private log is not a release asset. No host project files, Docker socket or host credentials are mounted into the runner. The runner does not remain online when the job ends; future live jobs require a new explicit launch. Ordinary hosted tests use offline doubles and do not need Ollama.

## Interview talk track

- **Problem:** generated syntax can be valid while business expectations are wrong.
- **Design:** bounded JSON actions, independent state/pricing checks, explicit review and fresh execution state.
- **Evidence:** literal controls, adversarial rejection, real HTTP, all-browser tests, pricing and observable mutants, model raw/corrected measurements and release receipts.
- **Tradeoffs:** SQLite and local services keep the lab reproducible; the reference shares invented policy facts; correction exposes the answer; an outbox gives reconciliation rather than a distributed transaction.
- **Learning:** use the reports to explain one rejected expectation and one interrupted payment, not only a passing badge.
