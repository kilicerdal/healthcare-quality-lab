# Healthcare Quality Lab V6.1 Engineering Report

## Why sequential E2E tests were not enough

A sequential rejection test cannot establish behavior under simultaneous writes, storage failure or a restarted process. V6.1 adds evidence at those boundaries and broadens mutation/property checking beyond the original twelve manually authored faults. All implementation is in `/Users/erdalkilic/Documents/Healthcare Quality Lab`. Other projects were not modified. VS Code was not opened. These milestones are delivered together in the V6.2.0 checkout; older published releases remain separate historical evidence.

## Real HTTP execution with the same reviewed cases

`http_runner.py` launches an isolated local application on an ephemeral loopback port per case, sends real HTTP requests, retains raw responses and projects the same business observations as the service runner. Hosts and actions are fixed by the application; model output cannot select arbitrary network targets. Temporary databases and listeners are cleaned up after the run.

Studio's execution selector chooses service or HTTP transport after the same approval gates. A run records its transport. Tests compare observed values for evaluator and payment-replay cases through both adapters. The HTTP adapter does not expose internal fault-injection switches. Its normalized generic validation error is documented, while the original response stays in raw evidence. Exported trusted pytest wrappers continue to default to the service adapter.

## Concurrency, storage failure and durability

Tests send sixteen competing payment operations through eight workers and verify exactly one payment, one ledger entry and the expected revision/history. Repeated concurrent submission with the same idempotency key returns one logical claim. A real SQLite trigger injects a ledger write failure, demonstrating transaction rollback and a valid subsequent retry. A seeded state-machine exercise checks valid and rejected lifecycle sequences; rejected operations cannot alter the stored evidence.

The bounded performance rehearsal uses forty local synthetic adjudications and reports median/P95 timings, rather than promising an SLA. Store reopening checks committed state. Packaged release stop/restart/rollback checks are recorded separately; they are not a claim of exhaustive crash consistency under every failure point. The preserved upstream engineering-proof page also supplies authored concurrent HTTP and interrupted-worker demonstrations, with no inference or writes to interactive claims.

## Broader mutation evidence

The new sweep mutates trusted repository pricing code through bounded arithmetic/min/max AST changes. It never executes AI-produced Python. Each mutant is compared with the separate Fraction oracle using cost-sharing, member/family limits and allocation witnesses.

Development results improved from 19/26 to 23/26, then 24/26, and finally **27/27** detected mutations. The improvements added nonzero balances, independent family/member/OOP states and explicit allocation-delta checks. Early tests had masked family-limit errors by correlating family balances with the individual's state. Detailed final original/mutated expressions and witnesses are retained in `mutation-sweep.json`; earlier observed counts are retained as development summaries.

This bounded 26-mutant sweep is separate from the original 12 known fault profiles, which remain intact. Neither score is repository-wide or exhaustive mutation coverage. The tests were strengthened using survivors, so the final sweep is a development result, not an independent holdout.

## Browser and visual verification

New and preserved journeys are exercised with Chromium, Firefox and WebKit in Linux. macOS driver failures are retained as infrastructure evidence rather than mislabeled test passes. The isolated Linux environment uses matching pinned packages and browsers; no source publication is needed for this validation.

Portable visual contracts compare geometry, heading placement and overflow, with screenshot evidence. They allow normal font-metric differences between Linux and macOS and are not exact cross-platform pixel goldens. Accessibility checks cover visible-control labels, keyboard focus and mobile overflow; they do not establish full WCAG compliance or replace assistive-technology testing.
