V7.9 — Team routing and portable release evidence

Purpose and location

A proposal needs an owner and an auditable inspection path. A release needs evidence that another engineer can download, verify and compare.

All implementation belongs to the existing standalone project at /Users/erdalkilic/Documents/Healthcare Quality Lab. No existing sibling project was modified and VS Code was not opened. This is a milestone in one combined V8 delivery, not a separately deployed application.

What was built and how

Engineering decision 1

The durable team ledger records assigned, changes_requested and ready_for_review decisions, bounded owner/note, actor and time. Events bind to case content, proposal revision, source and contract. Old routing history is retained but does not remain current after a snapshot changes.

Engineering decision 2

Shared mode records the authenticated username. Default local mode explicitly records a teaching attestation. Ready-for-review routing requires independent checks; it never grants approval. The existing explicit reviewer/admin approval boundary remains authoritative.

Engineering decision 3

Evidence packages accept explicit public docs/artifacts only, reject private state paths, and cover all ZIP members with a SHA-256 manifest and implementation provenance. Verification detects tampering and member mismatches; comparison lists added, removed and changed files without claiming equal-budget model accuracy.

Engineering decision 4

The V8 GitHub workflow defines Python 3.11/3.12/3.13 doctor, pip check, unit/API, actual adapter rehearsal and verified evidence packaging. The main release workflow points at V8 archives and includes the new browser journeys. Existing requirement-change impact analysis remains available in the Engineering hub.

Code and review map

Primary implementation and evidence entry points: healthcare_quality/team_workflow.py; tools/evidence_bundle.py; .github/workflows/v8.yml. Related behavior is exercised by the V8 unit/API/browser controls and the connected disposable rehearsal.

Why these choices

The implementation extends the existing DSL, independent reference, persistence and review gates instead of creating another incompatible framework. It keeps deterministic engineering checks usable without a model and retains original AI outputs. Explicit authorship, source fingerprints and separate review prevent a successful job or attractive screen from being mistaken for a correct model answer.

Validation and evidence

The milestone-specific checks and full final acceptance passed. The first extended checkpoint had 39 passing targeted checks; the final targeted set has 60. Final receipts, observed limitations and initial failures are retained below. No tests were skipped to hide failures.

Outcome and practical limits

Engineers can route work without confusing ownership with approval, and exchange immutable evidence with integrity checks. Checksums are not publisher signatures, and a local CI definition is not proof of a hosted passing run.

Synthetic policies and amounts are invented. Calculator-authored expectations are not AI financial reasoning. Reserved local inputs cease to be unexposed after actual inference. The reference HTTP sample is not a real external insurer. Read the final acceptance addendum before claiming a current passing build.

Measurement and operating boundaries

The interactive queue is a bounded view of the latest 50 advanced proposals. Historical routing events remain queryable for an individual proposal. Shared-lab access control and checksum integrity do not provide enterprise identity, external audit anchoring or a signed release.

Measured milestone outcome

Routing history persists, binds to a snapshot and does not approve. Evidence-bundle tampering, duplicate members, private path/symlink rejection and file comparison are tested. The V8 compatibility workflow defines Python 3.11/3.12/3.13 and actual adapter rehearsal. Hosted conclusions are only recorded after observing the runs.

Problems found and corrected

Initial validation exposed a Flask endpoint naming collision, a missing schema definition in the reference-peer endpoint, a missing route parameter, and the report route's missing/new heading contract. These were corrected rather than bypassing tests. The first Mac Firefox attempt could not launch its profile; Linux executed the complete Firefox suite. A recording selector failed on an icon-prefixed accessible name and was replaced by a stable navigation selector, with a workbench round-trip browser assertion. Final review also added duplicate-aware AI export, safe inspection of invalid saved proposals, symlink evidence rejection and one source fingerprint calculation per queue view. Original failed receipts remain in artifacts/v7.1-v8.0 and artifacts/v8.0/initial-*.
