# V5.2 assertion-completeness plan

Work only in the standalone Healthcare Quality Lab. Do not open or control VS Code.

- Separate structural DSL validity, assertion completeness and expected-value correctness.
- Require payout on valid evaluations and payout/payment/history/revision/status on successful workflow evidence. Rejected writes to a known case must have an unchanged-state readback.
- Constrain local generation with an outcome-specific schema and clearer assertion instructions. Preserve original drafts; never silently fill expected values from the application.
- Enforce a versioned completeness policy at review, execution and trusted pytest export. Preserve historical records and require fresh approval under the policy.
- Run focused regressions, full tests, real local Ollama paired baseline/new-generation measurements, reviewed assertion sensitivity, package/rollback and private GitHub CI.
- Deliver a detailed report with actual denominators, failures, limitations and preserved previous releases.
