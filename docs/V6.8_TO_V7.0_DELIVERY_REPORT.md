## Why the architecture changed

A useful scenario and a correct expected value are separate engineering problems. A model can choose meaningful payment actions yet calculate the wrong money, omit a ledger assertion or change an inconvenient scenario. V6.8 makes that distinction visible. AI-expectation mode measures the model's first attempt with no reference feedback. Calculator-backed mode uses AI for the bounded scenario and an independent lifecycle calculator for expected observations. Both stay unapproved until separate review.

The compiler reads inputs and written synthetic facts, never the application's responses. The independent reference does not import the production pricing function. Shared written facts still create common-mode risk; literal anchors, different property checks and defect experiments provide additional evidence, not a legal or production policy oracle.

Failure investigation retains actual requests, responses, request IDs, case snapshots and failed assertions. Content hashes detect alteration relative to the saved bundle. Deterministic triage remains separate from optional AI prose. Requirement links are derived from actions and observability mappings, not merely declared citations. A stored execution only counts as current passing coverage when case, contract, source and approval snapshots still match.

Durable generation/experiment records reserve their work before inference, preserve raw responses before later processing and fence late completions. Cancellation leaves unknown work unknown. Invalid explanation JSON and provider failures remain saved, and an unresolved explanation request cannot silently retry. Shared-mode role and CSRF controls cover every new endpoint; readiness checks the new stores.

## What actual AI achieved—and did not achieve

The V6.8 small model designed a valid scenario that compiled with correct calculator-authored values; its separate AI-authored expectations were wrong and blocked. In the V6.12 selected XP-03 comparison, two models and two prompts made four actual first-attempt requests. **All four raw answers were ineligible.** The focused prompt did not improve raw accuracy on this sample. Four calculator controls compiled without any model call and are explicitly excluded from model-reasoning metrics. One task per model/prompt is not a defensible general ranking or independent statistical sample.

An additional actual V7-development AI plan submitted an 88119-cent commercial PPO medical line, paid it and read it back. Calculator expectations were **61695-cent payout and 26424-cent member charge**. After explicit Codex engineering inspection, the copied generated case passed **1/1 actual isolated HTTP execution**. This required no reference-assisted correction, but its money was calculator-authored, not model reasoning. Its original generation provenance and pre-recording-fix source fingerprint remain intact.

V6.9's actual small-model explanation cited the failed payout assertion, agreed with the category and expressed uncertainty. The additional V7-development explanation cited existing evidence but chose the wrong category; it was rejected. These outcomes demonstrate the gate's purpose, not that AI explanations are always correct. No new paid API, cloud fallback or model download was used.

## What defect testing established

The original sixteen authored controls detected **25/27** production-pricing variants. Two survivors exposed a below-deductible copay boundary and a third-member family deductible with one cent remaining. Two explicitly authored controls close those gaps: their union with the original suite detects **27/27**. The single historical AI-designed scenario with calculator expectations detects **19/27**. The raw AI case earns no mutation score because it fails healthy behavior. Seeded generative/metamorphic properties detect **14/27**, with survivors retained.

Different suite sizes and known finite variants prevent an AI-superiority or exhaustive-coverage claim. The failing-prefix reducer preserves original inputs and expectations while producing a smaller reproducible failure; it does not fabricate a new oracle. Payment replay, reversal and old-response replay relations are also exercised against actual disposable SQLite state.

## Final verification, showcase and preservation

The accepted source passed **907/907** standard checks: **712 unit, 127 API and 68 Chromium**. The complete Linux sweep passed **1043/1043**: the same unit/API cases plus **68 E2E cases in each of Chromium, Firefox and WebKit**. Both have zero failures/skips. The twelve original evaluator/workflow seeds, nine actual HTTP integration fault scenarios and connected portfolio rehearsal passed. One upstream pytest-playwright deprecation warning remains recorded.

Earlier development failures remain visible: the missing initial report document, a duplicate DOM ID found by browser testing, and a recording-script URL-fragment navigation problem. Each was corrected and final verification rerun. Passing logs were not substituted for failed attempts. The final recording runs actual Chromium interactions, lasts about 81 seconds, retains captions/trace and makes zero model calls.

The separate personal editable presentation has eight visually reviewed slides, native architecture/table objects and speaker notes. Public previews accompany the source. The V6.7 presentation remains preserved. Optional ChatGPT, Copilot and Claude Code exercises remain learning exercises, not tools falsely claimed to have run; actual implementation/evidence used Codex, Ollama, pytest, Playwright, GitHub Actions and the presentation tooling.

Every original row in fourteen preexisting SQLite stores and the unrelated V4 working draft was verified unchanged. New stores and explicitly scripted records are additive. All work stayed inside the standalone project, and VS Code was never opened.

Hosted main, Python compatibility, complete browser and tag results are identified by the release's `github-ci.json`, which records exact commits and source fingerprints. The downloadable hosted archive is inspected against its manifest and rehearsed through actual upgrade, rollback and reactivation with isolated per-release state. This is a synthetic engineering showcase, not an actual Medicare policy engine, production payment processor or compliance certification.

## Accepted publication: V7.0.1

The initial complete hosted sweep exposed a WebKit configuration-readiness race in the legacy AI Studio. Generate is now disabled until model/rule configuration and saved-record hydration complete, with a shared initialization promise and an early-submit guard. A deterministic held-response regression verifies no early request and exactly one complete request afterward. The patch passed 51 related cross-browser checks and the final 907/1043 full suites. The unreleased V7.0.0 tag and failed run remain preserved; the accepted public release is V7.0.1, not a rewritten tag.
