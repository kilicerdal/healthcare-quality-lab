Healthcare Quality Lab V6.11 Engineering Report

November 18, 2026 · Standalone project: /Users/erdalkilic/Documents/Healthcare Quality Lab

Why we built this version

Passing healthy behavior is only half of a test's purpose. V6.11 asks whether a test detects deliberately wrong implementation behavior. It also prevents a bad AI oracle from earning credit simply because it fails against everything. The work builds on V6.10's traceable assertions and V6.9's evidence classification.

What we built and where

healthcare_quality/effectiveness.py derives bounded arithmetic/min/max variants from the project's trusted production pricing function. It compiles only that project-owned AST, never model-supplied code. A disposable service run temporarily substitutes each variant into the pricing dependency used by real benefit claims, then restores the original. tools.effectiveness compares labeled suites and writes concrete mutants, witnesses, survivors and baseline results. The read-only API/dashboard displays that saved experiment; the interactive server cannot launch production-patching jobs.

The experiment compares original authored controls, newly authored gap controls, historical raw AI cases and historical AI-designed cases with calculator expectations. It discloses the number of cases and distinct scenarios in each suite. These are not equal-budget model comparisons. Historical AI inputs are independently rechecked against current code; this offline experiment does not approve those proposals in the interactive Studio.

Baseline correctness before defect credit

Every scored suite must first pass healthy behavior and independently match the reference. The historical raw AI case has wrong financial expectations, so its failing baseline is reported as not scored, rather than being advertised as excellent defect detection. That distinction matters: a test that fails for the wrong reason is not evidence that it detects a real defect.

Each scored mutant records whether an assertion noticed the difference or valid input caused an exception. Surviving variants remain visible and may represent equivalent changes or missing scenarios; this finite set is not a complete model of all software defects. Production AST changes are also explicitly distinguished from V6.3's observable-contract perturbations.

Gaps found and closed

The initial original authored suite detected 25 of 27 variants. The two survivors concerned copay calculation when the amount is entirely inside the remaining deductible, and the family deductible when only one cent remains for a third family member. The initial evidence is retained under the development folder.

Two new controls are explicitly authored, not attributed to AI. A 5003-cent claim fully inside the remaining deductible must pay zero and charge the member 5003. The family control uses member amounts 9999 and 10000, then a third member's 50000-cent claim; the independent expected payout is 39199 cents and the family deductible reaches exactly 20000. These controls expose the two named variants. The combined authored result is a union across disclosed suites, not an improved AI-only score.

Generative and metamorphic checks

A seeded standard-library campaign generates bounded plan/service/date/amount combinations, with explicit deductible boundaries before random samples. It checks money conservation, nonnegative integer components, account limits, identifier-renaming invariance and equivalence of applying other-payer money before pricing the remaining amount. These are generative property checks; no Hypothesis dependency or exhaustive property proof is claimed.

Separate actual SQLite lifecycle relations verify that replaying payment returns its original response without creating another ledger/history/revision change, reversal balances the ledger and credits original accounts, and replaying an old payment after reversal cannot resurrect settlement. The property campaign is itself measured against mutants; survivors remain visible instead of being merged into the stronger authored result.

Smaller failure reproduction

A bounded prefix reducer searches for a shorter failing case against a named trusted mutant. It retains every surviving input and expected observation exactly, preserves the original case hash and requires a healthy baseline. It does not recalculate expectations to manufacture a failure. This is prefix-only reduction, not general delta debugging or minimization of financial values.

What we achieved

We now have reproducible evidence of which assertions notice real bounded pricing changes, which AI cases are unsuitable for scoring, which properties add value and how to reduce a failure for investigation. It strengthens the portfolio's central claim: test effectiveness must be demonstrated, not inferred from case count. The final JSON below is the authority for observed counts, budgets and survivors; no model is called by this milestone's effectiveness experiment.
