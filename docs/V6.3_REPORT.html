Healthcare Quality Lab V6.3 Engineering Report

November 18, 2026 · Standalone project: /Users/erdalkilic/Documents/Healthcare Quality Lab

Why this version exists

V6.2 could calculate advanced benefits, but its original AI language only described evaluate, submit, transition and read operations for the older workflow. An impressive advanced application did not automatically mean AI was testing it. V6.3 closes that gap with a separate benefit-case language, leaving the original Studio and saved evidence compatible.

What we built and where

All work is in the standalone Healthcare Quality Lab. advanced_schema.py defines the bounded language, advanced_reference.py models its lifecycle independently, advanced_runner.py executes it, and advanced_lab.py persists proposals and review snapshots. The engineering hub exposes generation, saved proposals, independent results, explicit review and HTTP execution. New state uses advanced-v63.sqlite; existing claim and Studio stores are not migrated or replaced.

The seven permitted actions are submit, pay, adjust, reverse, appeal, resolve and read. Every success must assert status, state, revision, event count, payout, member/other-payer/noncovered amounts, ledger balance/count, all member/family accumulators, policy ID and partial coverage. Known-claim write rejections require a subsequent authorized readback. Limits bound the number of cases, steps, lines, amounts, actors and keys. Extra fields, arbitrary URLs, shell actions and executable programs are rejected.

How we built the independent check

The new oracle is an in-memory state machine. It does not call BenefitClaims or the production pricing function to obtain an expected answer. It uses the separate Fraction calculator and independently tracks member/family accounts, reservations, revisions, events, idempotent responses, payment entries, adjustments, reversals and appeals. The oracle consumes step inputs, not proposed expected values, to advance its state. This prevents one incorrect AI assertion from defining the next expected state.

Sixteen authored controls cover all eight plan configurations and richer lifecycle combinations. Literal anchors include a fresh 100000-cent H1 commercial PPO medical payout of 71200 cents, an adjusted 50000-cent payout of 31200 cents, a zero net reversal ledger and restored accounts. A separate coordination example expects 55200 cents after 20000 cents from the other payer. Those values describe invented teaching contracts, not actual insurer coverage.

Schema correctness is necessary but insufficient. Review also requires a full independent match and no semantic duplicates. Duplicate normalization ignores generated claim IDs and operation-key spellings while preserving business inputs and replay relationships. A review binds the case, contract and source hashes. An edited source or changed scenario cannot reuse an old approval. Shared mode uses the authenticated reviewer identity and existing CSRF/role controls; the local reviewer label remains a clearly labeled teaching attestation.

What the actual AI demonstration means

The first real development attempt timed out while the 27B runtime processed its larger prompt. That failure is retained in artifacts/v6.3/live-development.json. It is not counted as an incorrect financial answer or a passing generated test. Advanced requests now use a separately named, bounded profile with 6000 output tokens, 16384 context tokens and a 240-second HTTP timeout; legacy requests retain their previous profile. Final raw results are recorded separately from this development failure.

The final current-source free-form 27B generation also returned a structurally invalid proposal. The schema gate blocked review and execution, and the original output is retained in artifacts/v6.3/live-current-generation.json. The workbench deliberately refuses a financial correction for structurally invalid input; it does not silently repair or approve that answer.

No proposal is automatically approved because its independent check passes. The runner uses fresh state per case and permits service or actual ephemeral loopback HTTP execution. Generated Python is never executed. Authored controls used in the showcase are labeled as authored, while actual Ollama measurements retain their original raw output and settings.

Outcome and limits

We now have an AI-facing test language that reaches the advanced benefit lifecycle and makes missing money/history/account assertions a validation failure. The reference still shares written plan facts with the application, so an incorrect common policy fact could affect both. It is an engineering oracle for a bounded synthetic system, not independent legal or clinical authority. The combined release evidence records final regression and browser results. Broader browser runs initially exposed startup races in the benefit, comparison and coverage views. Controls now remain disabled until the required configuration and authentication data are hydrated; deterministic held-request tests verify the behavior. Earlier development failures are retained, and the final complete suite passes.
