# Healthcare Quality Lab V6.8 Engineering Report

November 18, 2026 · Standalone project: `/Users/erdalkilic/Documents/Healthcare Quality Lab`

## Why we built this version

V6.7 proved that even a large local model could produce plausible but wrong payout and revision assertions. One example became correct only after reference-assisted feedback. That was useful, but it did not establish reliable first-attempt reasoning. V6.8 separates designing a useful scenario from computing the correct answer, so we can improve and measure each activity honestly.

## What we built and where

`healthcare_quality/test_design.py` defines a strict planning schema, a deterministic compiler, focused retrieval, versioned prompts and a persistent generation service. `design_api.py` adds explicit generation, inspection and export endpoints under the existing protected advanced API. A new workbench card and `static/design.js` expose both modes. State lives in a new `designs-v68.sqlite`; existing claims and experiment stores are not rewritten.

The first model call produces a risk, objective and bounded case containing actors, actions and business inputs. It must not supply expected observations. Existing constraints still limit allowed members, actions, line counts, step counts, integer amounts and identifiers. Arbitrary code and endpoints are not accepted. Invalid plans fail instead of being quietly rewritten into a passing example.

## The two modes and why the distinction matters

In **AI expectations** mode, a second local model call fills the expected observations for that exact plan. Focused retrieval supplies relevant synthetic plan facts, policy intervals, family relationships and written rules. It supplies no calculated expected answers or application responses. The independent gate checks all observations afterward and also verifies that the model preserved the original actors, inputs and action sequence. Incorrect values stay incorrect in the saved raw record; there is no correction call in this workflow.

In **calculator expectations** mode, the model designs the scenario and the independent in-memory lifecycle calculator supplies the expected observations. Those values are clearly labeled as calculator-authored, not model reasoning. This mode needs only the planning call. It is useful for constructing reliable executable test proposals while keeping the first mode available to evaluate AI reasoning. Both modes remain unapproved.

The compiler uses the independent reference state machine, not the application's claim service or pricing function. It advances from business inputs rather than from the model's proposed answers. It still shares written synthetic policy facts with the application, so common policy errors remain a documented limitation. Source and contract fingerprints bind the result to the implementation used during generation.

## How we built and tested the boundaries

Generation saves its initial record before inference, records the raw planning answer before starting a second request and retains failed provider output where available. A renewable lease and completion fencing prevent stale workers from overwriting later state. Expired generations become interrupted without automatically retrying, approving or executing anything. The generation semaphore coordinates with existing local AI jobs.

Tests exercise literal financial anchors, strict schema rejection, unknown fields, invalid money types, changed scenarios, incorrect first-attempt answers, provider failure after planning, both authorship modes and blocked export. Chromium checks verify that navigation makes no generation request and that the two modes and blocked export are visible. The initial full API run exposed a missing current-version report document; the report is created before final milestone validation rather than weakening the report-serving test.

## What we achieved

We now have a measurable plan-first process and an honest practical alternative to asking a language model to calculate every insurance amount. A checked design can be explicitly exported to the existing advanced Studio, where separate snapshot-bound review and execution still apply. Export is neither approval nor a claim that someone inspected it.

Actual small-model attempts are retained below, including failures. A successful compiler result is not reported as improved raw AI accuracy, and a failed plan is not repaired invisibly. The next milestones will investigate failures, connect requirements to assertions and compare actual defect detection. We do not promise that this prompt makes every model answer correct.
