Why this version exists

A project can be technically strong and still be hard to present. The showcase should let another engineer understand the problem, reproduce a bounded experiment and inspect the supporting evidence without needing this chat. V6.6 adds a coherent presentation path around the delivered framework.

Deliverables

The interview presentation is saved in the owner's personal Spaces library, with editable diagrams/text and speaker notes. It follows the existing green Healthcare Quality Lab visual style. A repository interview guide supplies the same public narrative for people who cannot access the personal deck. The architecture walkthrough explains the application, independent oracle, proposal/review boundary, local-model runtime, ephemeral CI runner, synthetic external peer and durable stores.

tools.record_advanced records actual headless Chromium UI actions and creates a WebM, WebVTT captions and a source-linked capture receipt. The recording loads an explicitly authored adjustment control, inspects and approves its snapshot, executes it through fresh HTTP state, displays separately recorded model measurements, and runs lost-acknowledgement and webhook-replay rehearsals. It finishes at the readiness/release showcase. Captions distinguish authored controls from historical live AI evidence. The recording itself makes no inference call and has no synthetic voiceover.

This distinction matters: a replay or an authored test can demonstrate engineering behavior without proving that AI freshly generated it. The historical model table is labeled as prior actual measurement, including invalid/wrong results. We do not edit those results into a successful story. The video depicts real application responses and retained assertions, not static mock screens.

Reproduction and release

The existing fresh-demo launcher retains its refusal to overwrite state. The expanded replay seeds labeled authored advanced evidence and copies recorded model experiments with their original provenance. These are new isolated stores; existing interactive claims, experiments and the unrelated V4 draft remain preserved. Runtime requirements and matching browser tooling remain project-local.

The public tagged release is the combined V6.7 delivery of all five milestones. Its downloadable assets include the verified source archive and manifest, per-version reports, the captioned demonstration, current verification/CI receipts and bounded model/integration evidence. The source checksum verifies integrity and the source fingerprint binds implementation to test evidence. Those are not a cryptographic publisher signature or proof of legal coverage correctness. Earlier archives and release tags remain unchanged.

The interview guide is organized as an engineering argument: what can go wrong with an AI expected value, how the independent gate catches it, why review is separate, what actual execution proves, how cross-service ambiguity is reconciled and what the measurements do not prove. Learning exercises for ChatGPT, Copilot and Claude Code are labeled exercises; access to those tools or actual usage is not invented. Codex, local Ollama, pytest/Playwright and GitHub Actions have concrete roles in the implementation and evidence.

Outcome and limits

The project can be presented as a connected engineering workflow rather than a feature list. The local demo, public source, reports, captured UI and remote receipts provide reviewable artifacts. The personal Spaces deck is a companion artifact, not a publicly hosted healthcare application. Real Medicare policy, production identity/payments, accessibility certification and exhaustive reliability remain outside this synthetic lab.
