## Why the framework was built this way

The purpose is to demonstrate how engineering establishes trust in an AI-assisted test—not merely how to ask a model to write one. Written synthetic contracts define behavior. Independent calculators check expected values. Approval binds an exact snapshot. Service/HTTP execution records observations. Controlled faults and mutation/property checks measure test sensitivity. Failures and model limitations remain visible.

The new advanced benefit engine is separate from the original simple evaluator because changing its formula would invalidate historical learning evidence and confuse old expected payouts. The new policy file and database namespace make the different contracts explicit. The AI case language remains bounded; no model-produced executable Python, shell command, file path or arbitrary URL becomes runnable.

## Shared identity and audit

Default local mode retains clearly labeled teaching actors and loopback serving. Optional shared mode requires configured password hashes and an external session secret of at least 32 characters; there are no default credentials or insecure fallback. Login is rate limited, cookies are HttpOnly/SameSite, modifying requests require CSRF, and a caller cannot spoof another actor. Configured reviewer/admin roles control approval. The server replaces caller-supplied reviewer labels and saves authenticated identity with the approval.

The audit store records identity, request ID, method, fixed route and status, not request bodies, passwords or query strings. A hash-linked sequence detects modification/reordering. It has no external immutable anchor, and a privileged administrator could replace the whole chain. Audit and application stores are not one distributed transaction. This is a useful local/shared-lab control, not a production identity platform or compliance certification. Use TLS and deployment-specific protections before any non-loopback deployment; this delivery does not expose a public healthcare service.

## Limits and what was achieved

This is a synthetic engineering lab. It does not implement actual Medicare law, clinical decisions, a complete payer platform, external payments, distributed queues, HIPAA certification, full WCAG certification or exhaustive mutation coverage. The new benefit rules are deliberately bounded. Historical reversals credit their allocations without repricing later claims. Copay fields describe nominal intermediate amounts before OOP caps. AI-generated executable cases remain in the original four-action language; new benefit scenarios use authored and property/browser tests.

Within those limits, the requested features now form a connected, reproducible workflow: define a rule, generate a proposal, check its oracle, review identity/snapshot, execute through a real boundary, investigate a failure, measure defect sensitivity, exercise financial state and retain release evidence. The deliverable is stronger because it keeps the failures and boundaries visible, not because it promises flawless AI.
