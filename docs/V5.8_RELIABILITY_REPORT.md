## What was built and how it works

`healthcare_quality/data/reserved_v58.json` contains eight new literal synthetic outcomes, authored before the new inference batch. They cover different plan/service combinations, cost boundaries and denial precedence. Expected outcomes are kept out of generation prompts and independently cross-checked against the existing reference in tests. No prompt was tuned using the resulting answers.

`healthcare_quality/reliability.py` persists a batch before inference, records selected models, task IDs, repeats, settings, dataset hash and focused-protocol/reference fingerprints, then evaluates each raw response. The model sees the existing one-plan focused prompt, never the dataset's expected answer. The response must satisfy the output schema, fixed inputs, complete assertions, independent reference and structured calculation, as well as the separate literal outcome.

Each batch is bounded to 24 requests, at most three models and three repeats. A database heartbeat lease prevents two workers from claiming the same evaluation capacity. Studio's inference semaphore is shared within the application. Expired jobs become interrupted with partial evidence retained. Explicit cancellation fences late writes; an already running provider request can take up to its timeout to return. A protocol/reference change stops the remaining work. There is no automatic correction, approval, export or test execution in this benchmark.

The engineering hub exposes batch controls and saved raw evidence. The opt-in CLI is `python -m tools.reliability --models qwen3.5:27b --tasks R01 R02 R03 R04 --repeats 2 --state .local/new-evaluation.sqlite --output artifacts/new-evaluation.json`. Choose a fresh output; evidence is not overwritten.

## Actual measured outcome

Four of the eight reserved inputs were each evaluated twice with each of two installed models: 16 completed responses. Four additional inputs remain unmeasured. Settings are deterministic, including the same seed and temperature; repeated results are correlated, not independent statistical samples.

| Model | Strict correct | Exact case assertions | Errors | Median | P95 |
| --- | --- | --- | --- | --- | --- |
| qwen3.5:27b | 8/8 | 8/8 | 0 | 31.07s | 49.36s |
| qwen2.5-coder:3b | 0/8 | 0/8 | 0 | 3.55s | 5.77s |

A strict failure can arise from the case assertions, the calculation summary, or both. It does not imply every assertion in that response was wrong. The table separates literal case matches from full eligibility. The larger model was slower and passed this small cohort; that is a measured tradeoff, not evidence it is always the best model.

An earlier batch ran while Ollama was stopped. Its 16 connection failures are retained separately in `artifacts/v5.8/reserved-live.json`; they are infrastructure failures, not incorrect model answers. The online batch remains in `reserved-live-online.json`. The exposure flag conservatively records the earlier batch, so the online result is not represented as an untouched statistically independent holdout.

## Validation, outcome and limits

Tests exercise literal outcomes, repeat aggregation, invalid budgets, raw failure recording, exposure labels, cross-worker leases and cancellation fencing. Integration tests confirm that refreshing the hub does not start inference and that users must explicitly request a batch. The final combined release passed 736 deterministic tests; the real-model measurements above are separate from offline CI doubles.

We achieved a reproducible way to question AI reliability rather than count generated tests. This is still only four measured input combinations. The frozen dataset and prompts share authored teaching facts; common fixture mistakes remain possible. No production benefit, clinical or compliance claim follows from the result.
