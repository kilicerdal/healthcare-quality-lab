# V7.4 — Synthetic healthcare coverage packs

## Purpose and location

Coverage breadth should be visible as executable requirements and boundary scenarios rather than a list of insurance names in a presentation.

All implementation belongs to the existing standalone project at `/Users/erdalkilic/Documents/Healthcare Quality Lab`. No existing sibling project was modified and VS Code was not opened. This is a milestone in one combined V8 delivery, not a separately deployed application.

## What was built and how

### Engineering decision 1

Eight versioned packs cover Medicare Part A, Part B, Advantage/Part C, Part D, commercial PPO, commercial HMO, dental and vision. Advantage and Part C are one pack. Each pack exposes services, scope, assumptions and an explicit real_world_policy=false flag.

### Engineering decision 2

Every pack includes covered, noncovered and deductible boundaries. Network, authorization and formulary boundaries are added where applicable. Each scenario submits, pays and reads the same claim, with full independent observations on every successful step.

### Engineering decision 3

The pack generator produces action inputs, then the separate lifecycle calculator authors expected money, ledger, event-count, revision and account observations. It never records the production application response as an expected answer.

### Engineering decision 4

The packs share the existing invented BN cost model. They do not model real Part-D phases, actual Medicare eligibility, plan documents or certified commercial coverage. No current policy or medical claims are asserted.

## Code and review map

Primary implementation and evidence entry points: `healthcare_quality/coverage_packs.py; healthcare_quality/static/workbench.js; tests/unit/test_v8_foundations.py`. Related behavior is exercised by the V8 unit/API/browser controls and the connected disposable rehearsal.

## Why these choices

The implementation extends the existing DSL, independent reference, persistence and review gates instead of creating another incompatible framework. It keeps deterministic engineering checks usable without a model and retains original AI outputs. Explicit authorship, source fingerprints and separate review prevent a successful job or attractive screen from being mistaken for a correct model answer.

## Problems found and corrected

Initial validation exposed a Flask endpoint naming collision, a missing schema definition in the reference-peer endpoint, a missing route parameter, and the report route's missing/new heading contract. These were corrected rather than bypassing tests. The first Mac Firefox attempt could not launch its profile; Linux executed the complete Firefox suite. Final review also added duplicate-aware AI export, safe inspection of invalid saved proposals, symlink evidence rejection and one source fingerprint calculation per queue view.
