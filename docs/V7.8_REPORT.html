V7.8 — Governed evidence and AI assistant

Purpose and location

An assistant should reduce inspection work while keeping evidence, inference, authorship and approval distinguishable.

All implementation belongs to the existing standalone project at /Users/erdalkilic/Documents/Healthcare Quality Lab. No existing sibling project was modified and VS Code was not opened. This is a milestone in one combined V8 delivery, not a separately deployed application.

What was built and how

Engineering decision 1

The evidence assistant returns deterministic saved facts with proposal/case/run citations, quality issues, recommendations and explicit uncertainty. Its response declares can_approve=false, can_execute=false and live_model_calls=0.

Engineering decision 2

A gap view identifies plan families absent from supplied proposal inputs. It explicitly does not count proposal presence as executed passing coverage. It does not invent a model-based root cause.

Engineering decision 3

The separate local AI action calls the existing allowlisted Ollama planner with bounded synthetic requirements. The model designs inputs only; independent calculator expectations are labeled. Saved design inspection performs no new inference. Export requires the quality and freshness gates.

Engineering decision 4

All writes are explicit, proposals start unapproved, and routing cannot approve. The existing identity-bound AdvancedLab review and actual isolated execution remain separate. The assistant has no arbitrary code, shell, browser, database or network tools.

Code and review map

Primary implementation and evidence entry points: healthcare_quality/assistant_v8.py; healthcare_quality/workbench_api.py; healthcare_quality/static/workbench.js. Related behavior is exercised by the V8 unit/API/browser controls and the connected disposable rehearsal.

Why these choices

The implementation extends the existing DSL, independent reference, persistence and review gates instead of creating another incompatible framework. It keeps deterministic engineering checks usable without a model and retains original AI outputs. Explicit authorship, source fingerprints and separate review prevent a successful job or attractive screen from being mistaken for a correct model answer.

Validation and evidence

The milestone-specific checks and full final acceptance passed. The first extended checkpoint had 39 passing targeted checks; the final targeted set has 60. Final receipts, observed limitations and initial failures are retained below. No tests were skipped to hide failures.

Outcome and practical limits

The workbench offers useful cited evidence assistance and actual optional AI planning without allowing the model to approve or silently execute its own proposal.

Synthetic policies and amounts are invented. Calculator-authored expectations are not AI financial reasoning. Reserved local inputs cease to be unexposed after actual inference. The reference HTTP sample is not a real external insurer. Read the final acceptance addendum before claiming a current passing build.
