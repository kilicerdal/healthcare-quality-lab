# V7.7 — Security, dependency and resilience evidence

## Purpose and location

Functional pass counts alone do not establish that permissions, interrupted work or competing payments behave correctly. This milestone adds evidence around those operational boundaries.

All implementation belongs to the existing standalone project at `/Users/erdalkilic/Documents/Healthcare Quality Lab`. No existing sibling project was modified and VS Code was not opened. This is a milestone in one combined V8 delivery, not a separately deployed application.

## What was built and how

### Engineering decision 1

New APIs live under the existing authenticated advanced prefix. Tests verify unauthenticated rejection, auditor read-only access, customer rejection, analyst/reviewer write access, missing-CSRF rejection and separate approval requirements. Both new SQLite stores are included in readiness.

### Engineering decision 2

The dependency scanner explicitly queries OSV for installed public Python package names and versions. A malformed, incomplete or unreachable lookup returns unknown; known advisories remain findings. It never interprets a network failure as a clean scan.

### Engineering decision 3

The existing trusted resilience campaign is rerun against the extended runtime: bounded submissions, 16 competing payment attempts, restart readback and injected database-write failure with rollback. The cross-system campaign adds 24 concurrent workbench reads with four workers.

### Engineering decision 4

Durable experiments retain existing leases, cancellation and late-response fencing. Tests verify that expanded-cohort calculator controls make zero provider calls and that raw provider failures remain failed rows without correction or cloud fallback. These are bounded engineering controls, not a penetration test or capacity certification.

## Code and review map

## Why these choices

The implementation extends the existing DSL, independent reference, persistence and review gates instead of creating another incompatible framework. It keeps deterministic engineering checks usable without a model and retains original AI outputs. Explicit authorship, source fingerprints and separate review prevent a successful job or attractive screen from being mistaken for a correct model answer.

## Problems found and corrected

Initial validation exposed a Flask endpoint naming collision, a missing schema definition in the reference-peer endpoint, a missing route parameter, and the report route's missing/new heading contract. These were corrected rather than bypassing tests. The first Mac Firefox attempt could not launch its profile; Linux executed the complete Firefox suite. A recording selector failed on an icon-prefixed accessible name and was replaced by a stable navigation selector, with a workbench round-trip browser assertion. Final review also added duplicate-aware AI export, safe inspection of invalid saved proposals, symlink evidence rejection and one source fingerprint calculation per queue view. Original failed receipts remain in artifacts/v7.1-v8.0 and artifacts/v8.0/initial-*.
