# V7.1 — Reliable installation

## Purpose and location

A framework is difficult to learn or demonstrate if only its author can start it. This milestone makes runtime readiness inspectable and gives a new engineer a repeatable installation path.

All implementation belongs to the existing standalone project at `/Users/erdalkilic/Documents/Healthcare Quality Lab`. No existing sibling project was modified and VS Code was not opened. This is a milestone in one combined V8 delivery, not a separately deployed application.

## What was built and how

### Engineering decision 1

The new read-only doctor checks supported Python 3.11–3.13, exact pinned runtime distributions and required synthetic source fixtures. Its output is structured JSON and its exit status can be used in CI.

### Engineering decision 2

Ollama status is an explicit optional check. An unavailable model service does not make the deterministic runtime unusable. The doctor never installs dependencies, downloads models, alters a project or starts inference.

### Engineering decision 3

The existing one-command fresh demo remains the installation path. It creates project-local dependencies and refuses existing nonempty state. The guide explains Windows interpreter paths, occupied ports, unavailable package downloads and missing browser binaries.

### Engineering decision 4

Runtime diagnosis is deliberately separate from browser installation. A ready doctor result is not proof that Firefox, WebKit, external services or production hosting are available.

## Code and review map

Primary implementation and evidence entry points: `tools/doctor.py; tools/bootstrap.py; tools/launch_demo.py; docs/V8_GUIDE.md`. Related behavior is exercised by the V8 unit/API/browser controls and the connected disposable rehearsal.

## Why these choices

The implementation extends the existing DSL, independent reference, persistence and review gates instead of creating another incompatible framework. It keeps deterministic engineering checks usable without a model and retains original AI outputs. Explicit authorship, source fingerprints and separate review prevent a successful job or attractive screen from being mistaken for a correct model answer.

## Outcome and practical limits

A new engineer can distinguish a missing dependency from an optional model capability, start a fresh synthetic demonstration and preserve existing state.

Synthetic policies and amounts are invented. Calculator-authored expectations are not AI financial reasoning. Reserved local inputs cease to be unexposed after actual inference. The reference HTTP sample is not a real external insurer. Read the final acceptance addendum before claiming a current passing build.

## Problems found and corrected

Initial validation exposed a Flask endpoint naming collision, a missing schema definition in the reference-peer endpoint, a missing route parameter, and the report route's missing/new heading contract. These were corrected rather than bypassing tests. The first Mac Firefox attempt could not launch its profile; Linux executed the complete Firefox suite. A recording selector failed on an icon-prefixed accessible name and was replaced by a stable navigation selector, with a workbench round-trip browser assertion. Final review also added duplicate-aware AI export, safe inspection of invalid saved proposals, symlink evidence rejection and one source fingerprint calculation per queue view.
