Healthcare Quality Lab V8.2 Engineering Report

Outcome and purpose

Engineering implementation is complete. Final local verification passed 1070/1070 checks, and hosted full-browser verification passed 246/246 checks. All six prior surviving pricing faults now have authored detecting witnesses. The extended AI qualification was stopped for timely delivery and is explicitly INCOMPLETE.

V8.2 addresses four concrete problems from V8.1: unreliable model-authored expected values, expensive repeated output and timeouts, six surviving pricing faults, and a dashboard that made it difficult to distinguish the kinds of failure. The implementation stays in the existing standalone /Users/erdalkilic/Documents/Healthcare Quality Lab. VS Code was not opened. Sibling projects and the unrelated V4 report draft were preserved.

The intended outcome is an inspectable framework that can demonstrate which model-authored tests work, block wrong predictions, and expose gaps with reproducible evidence. A passing engineering suite does not mean every AI answer is correct. The measured qualification results later in this report determine what reliability claims this version supports.

What we built and why

Compact model-authored quotes

V8.1 asked the model to repeat a complete financial observation and substantial worksheets across submit, payment, read and replay. Repetition increased output cost and created more opportunities to change a number accidentally. V8.2 lets the model write a financial quote once, then reference its own quote ID in subsequent observations.

Each quote contains a model-authored pricing worksheet and twelve financial/account/policy values. Each observation supplies its immutable step ID, a quote reference, a stored-ledger worksheet and six lifecycle fields. The parser copies the referenced model values into the existing eighteen-field test observation. It performs no pricing arithmetic, ledger increment, state transition, inference, correction or reference lookup.

If used accounts change, the model must supply a new quote even if the payout is unchanged. Unknown, duplicate and unused quote IDs are rejected. Missing, duplicate or reordered step IDs are rejected. The original actors, actions, dates, amounts, operation keys and business inputs remain immutable.

This is AI-assisted test authorship: engineering supplies the input scenario; the model authors expected values and auditable numeric records. It is not a claim that the model invented every input scenario.

Focused cap calculations

The first compact development attempt was faster but arithmetically wrong. A second attempt restored a single pricing worksheet per quote, but the larger model still stopped at preliminary coinsurance and ignored the final OOP cap. V8.2 therefore makes the cap decision explicit before final values:

  • Calculate eligible cents after another payer, nominal deductible, copay and the integer-floor preliminary payer amount.
  • Write remaining individual OOP, remaining family OOP, capped member cost and remaining annual benefit.
  • Calculate payer after the member cap, final payout after the benefit cap, and noncovered cents.
  • Update used accounts by the actual allocation, not policy limits and not prior balances plus new balances.

These are model-authored numeric records. Independent checking happens after generation freezes. The server does not fill a missing cap or replace a wrong result. Rejected-coverage worksheets explicitly use zero member-before-OOP and zero payer-after-OOP; rejected money is noncovered money, not a member charge.

The partial rule also receives a clear definition: covered and rejected-coverage lines must coexist in a claim. One wholly unauthorized or out-of-network claim is not automatically partial, and benefit-cap excess on covered lines does not by itself change this flag.

Stored-ledger calculations

Once the cap calculation was correct, development exposed another error: the model placed the calculated payout in the submit ledger before payment occurred. V8.2 adds a small stored-ledger worksheet before each lifecycle observation: balance before, signed change and balance after.

Adjudication reserves benefit accounts but posts no payment. Payment adds the payout, even if it is zero. A read or identical replay adds nothing. Reversal credits this claim's allocation. A replayed response may contain an old response snapshot while the stored claim stays unchanged; those two concepts are distinct.

The model authors the ledger worksheet and the expected ledger observation. Both must independently match. The worksheet does not calculate a replacement expected ledger amount for the model.

Independent gate and changed scoring contract

The V8.2 strict gate requires complete correct API observations, correct pricing/cap worksheets on pricing actions, and correct stored-ledger worksheets on all steps. Canonical JSON comparisons distinguish integer zero from false and 0.0 when rechecking stored worksheets. Wrong worksheets block export even if the final payout happens to be right.

V8.1 additionally required its separate before/after revision/event state worksheets. V8.2 adds explicit cap-decision records and a signed ledger change while removing those redundant revision/event worksheets. Revision and event count are still mandatory and independently checked in every successful expected observation. The strict rubrics differ: their percentages are not interchangeable measures.

Both versions' complete-observation correctness remains visible separately. The qualification cohorts also differ, so the historical and new results are not a matched before/after accuracy experiment.

Bounded local inference and explicit provenance

The final profile requests temperature 0, seed 7, maximum 2600 output tokens and context 12288. It keeps the existing V8.1 maximum request deadline of 240 seconds. Earlier development used a 150-second deadline; the final choice retains the common deadline for the more demanding multi-claim inputs. Timeout reduction is pursued through less repeated output, not through hiding failures or silently extending requests beyond the baseline limit.

The larger installed MLX-backed model uses prompt JSON validation; the small model uses schema-constrained output. Requested settings and seed are recorded, but do not prove identical backend implementation or determinism. There is no paid/cloud fallback, model download, arithmetic tool, hidden retry or automatic correction.

The shared durable lab accepts an injected protocol and evaluator. Its default behavior preserves V8.1. V8.2 uses a separate cohort, store and API. Leases, heartbeats, source/contract fences, restart recovery, cancellation, raw final responses, exposure tracking and request budgets remain in place. Request start time, elapsed time, provider failure, timeout, invalid output and wrong-observation counts are recorded explicitly, along with the request timeout setting.

Readable dashboard

The new workbench panel separates correct trials, wrong expected values, wrong numeric worksheets, invalid output, timeouts, output-limit failures, other provider errors and unavailable stages. It shows planned denominators, model/stage, request counts and elapsed time. Completed-response median latency is labeled; failed requests remain separately visible rather than disappearing from correctness denominators.

Raw prompts and JSON are collapsed by default. Data is rendered as text, not HTML. Configuration failure keeps generation disabled. Starting inference is explicit; refreshing saved results and loading the fault catalog make zero model calls. Blind self-review defaults off because V8.1's measured blind reviews recovered zero strict failures and added inference cost.

Export independently rechecks a completed current-source answer and creates an unapproved proposal with unchanged model values. Inspection, review and actual HTTP execution remain separate actions. The dashboard labels authored fault witnesses separately from actual AI coverage.

What timeout improvements are proved

Compact encoding removes repeated financial quotes and repeated pricing worksheets on payment/read steps. All selected final development cases completed within the earlier 150-second development limit; final requests retain the common 240-second maximum deadline for multi-claim inputs. The final larger-model development latencies were approximately 105.4s (cap),88.6s (unauthorized coverage),103.3s (replay).

This establishes working bounded compact generation on those development cases. It does not prove a lower general timeout rate: the fresh extended evaluation is incomplete, cohorts differ, and development ran alongside other validation work. The report makes no completed-population speedup, zero-timeout guarantee or native-reasoning claim. Native reasoning was not enabled.

What we achieved

V8.2 delivers a professional compact prediction path with explicit cap and ledger decisions, strict independent gates, clear failure categories and reproducible fault witnesses. It fixes the selected cap, unauthorized-coverage and replay development cases and confirms cap/unauthorized cases on two fresh repeats each. It exposes all six previously surviving pricing faults through separately labeled authored tests.

The engineering implementation is ready for review and showcasing. Broad AI reliability remains unqualified because the extended run was stopped. Vision/mixed-coverage failures and the remaining unmeasured used-balance cases remain visible work for a future explicitly time-budgeted evaluation. This report does not call the model flawless or autonomous.

The useful next step is a short, separately agreed evaluation budget, a genuinely new reserved cohort after development fixes, and reuse of the frozen implementation rather than another open-ended feature expansion. ChatGPT, Copilot and Claude Code were not invoked by this milestone; actual generation used the installed local models. Adding more tool names would not substitute for better measured predictions.
