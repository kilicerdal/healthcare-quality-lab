
No historical experiment IDs, installed model or API key are needed for the authored demonstrations. Two authored synthetic workflow records are seeded for the workflow desk; no AI proposal is automatically approved.

## Two-minute story

1. **0:00–0:20 — State the risk.** A successful response does not prove that a payment or test expectation is correct. Every amount here is invented.
2. **0:20–0:45 — Question the oracle.** Run the plausible wrong expectation. The payout mistakenly ignores the deductible. Inspect the independent mismatch, corrected authored expectation, healthy control and observed seeded defect. This learning example was authored, not generated during the demo. Generated cases still require explicit Studio review.
3. **0:45–1:10 — Competing requests.** Run two simultaneous payment requests. Inspect actual HTTP 200/409 outcomes, distinct request IDs, one payment, revision three and three committed history events.
4. **1:10–1:35 — Recovery.** Run the worker interruption. The child process exits after writes but before commit. Compare the approved state before/after rollback, successful retry and rejected replay. This is local SQLite process recovery, not a distributed payment guarantee.
5. **1:35–1:50 — Change the requirement.** An isolated what-if raises the deductible. Actual Studio review freshness checks block execution under the changed reference. No running application facts are patched.
6. **1:50–2:00 — Inspect AI evidence.** Open a recorded provider trial. Show raw output, independent expected values, rejected calculations, repeatability and cost estimates. Nothing calls a provider on page load.

## Live provider evaluation is separate

Only explicit CLI commands can use a paid provider. Normal tests and the UI do not read OpenAI credentials. The runner requires `--allow-paid`, uses a persistent budget ledger, reserves a conservative request allowance and stops on uncertain charges without retrying.

The newly authored cohort contains sixteen inputs not present in the previous V5.7 cohort. Scenario families are known; this is not a blind holdout. Both providers receive the same base prompt, schema and inputs. Their decoding, transport, hardware and model sizes differ. Local Ollama uses temperature zero/seed seven and its recorded prompt-JSON mode; OpenAI uses low reasoning and strict schema output. Repeatability describes these particular settings, not stochastic robustness or general accuracy.

Paid evaluation accepts `OPENAI_API_KEY` from the process environment or an explicitly selected local env file. Never commit an API key, an env file, or the budget SQLite database. The live run report records measured token usage, a usage-derived cost estimate, and a separate conservative reserved bound; it is not a billing invoice. The $15 cap applies to this evaluation ledger, not unrelated account activity.

Inspect eligible proposals before any explicit human review and execution. No provider output from this comparison is automatically approved or executed.
