# V8.1 operator and evaluation guide

## What “without calculator assistance” means

The model receives fixed synthetic inputs, relevant written rules, applicable plan/policy facts, an output schema and explicit arithmetic/state formulas. It receives no computed answers, reference mismatches, application responses, arithmetic tools or executable code. It authors every expected observation and numeric worksheet value.

The independent calculator evaluates answers only after the original and optional blind self-review are frozen. It never fills or repairs values. Export copies the model's expectations unchanged into immutable input steps; a separate inspection and actual isolated HTTP execution remain required. Accounting notes are unverified model text, not evidence of correct reasoning.

## Use the workbench

Open the local application at `/#workbench` and find “Can the model predict the correct result?” Select an installed local model and a development scenario before running a new experiment. The run button is explicit; page loads, saved-record refreshes and status reads never request inference.

Whole-case mode requests all observations once. Stepwise mode requests each observation using only the model's own earlier unverified predictions. The checkbox adds one blind self-review; it is scored separately and never credited as first-attempt success. The model's original responses remain intact even when a later answer changes them.

Inspect the request budget, original JSON, worksheets, strict score and source freshness. Export one eligible first-attempt or self-reviewed answer as an unapproved proposal. Inspect the money, revision/event counters, ledger and accumulators before separate approval and HTTP execution. Wrong worksheets, missing IDs, stale source and incorrect observations block export.

## Reproduce the frozen protocol

```sh
.venv/bin/python -m tools.expectations --models qwen2.5-coder:3b qwen3.5:27b --tasks H81-01 H81-02 H81-03 H81-04 H81-05 --self-review --state .local/my-v81.sqlite --output artifacts/v8.1/my-part-one.json --dry-run
```

This declares 20 model requests: five cases × two models × first attempt plus blind review. Remove `--dry-run` only when you intend to expose those inputs to the models. Run the second batch with H81-06 through H81-10 and a different output file. Then:

```sh
.venv/bin/python -m tools.expectation_report artifacts/v8.1/my-part-one.json artifacts/v8.1/my-part-two.json --output artifacts/v8.1/my-scorecard.json
```

Original files cannot be overwritten. The analyzer refuses duplicate trial identities and mixed source, cohort, strategy, runtime profile or model digests. All planned rows remain in denominators, including provider failures and unassessed answers. Ten unique reserved cases per model are required before the predeclared 80% target can be met; repeated trials do not create more unique cases. Cases are no longer unexposed after a request, and exposure tracking is ledger-relative, not proof of globally unseen training data.

Use D81-01 through D81-04 for development. The H81 cohort was locked before this delivery's held-out run; its published results now make it exposed. Create a new reserved cohort before making a new unseen-evaluation claim. Do not tune prompts against these held-out answers and continue calling the results blind.

## Runtime profiles

The default V8.1 direct profile requests temperature 0, seed 7, 6000 output tokens, 16384 context and a 240-second transport timeout. The larger installed model uses prompt-JSON validation because its MLX runtime does not provide constrained JSON output. The small model uses schema-constrained output; the portable contract avoids the boolean `items` schema rejected during development.

The explicit CLI flag `--native-reasoning` selects the development reasoning profile with 10000 output tokens, 24576 context and a 420-second timeout. The installed larger model advertises thinking support, but the tested native-reasoning request timed out without a usable final answer. It was not selected for the qualification run. Internal deliberation text is omitted from retained envelopes; final JSON, numeric worksheets and requested settings remain auditable. No model is pulled, no cloud fallback occurs and no paid API is invoked by these commands.

## Interpret the evidence

First-attempt correctness, blind self-review correctness, monetary/state worksheets and observation correctness are separate measures. A self-review can repair or damage an answer; paired outcomes report both. Input preservation is guaranteed by server assembly, not evidence that the model became better at rewriting scenarios. One correct development case cannot qualify a model.

Strict eligibility requires complete, independently matching observations and all numeric worksheets. A provider timeout is an unavailable answer, not proof of incorrect arithmetic. Schema failure is different from a completed wrong financial answer. Correct observations with an incorrect worksheet still fail the strict gate. The default mode remains experimental and every executable proposal requires review.

## Test and troubleshoot

```sh
.venv/bin/python -m pytest tests/unit/test_expectation* tests/api/test_expectation_api.py tests/e2e/test_expectations_browser.py -q
.venv/bin/python -m tools.verify
```

These checks use offline provider doubles; their passing fixtures are not real-model accuracy. Actual local experiments have separate raw responses, model digests and source fingerprints. Cancellation preserves unfinished requests and fences late responses; it never silently retries. Model/backend errors retain bounded response details when available. Choose a fresh output file and dedicated state ledger rather than deleting existing project data.


## Replay the published measurements without inference

Start a fresh demo using the README command. To load the delivered records into that new demo, run the following from the project environment, substituting its dedicated state directory. This copies recorded experiments only; it does not copy approvals, call a model or replace the published evidence files.

```python
import json
from pathlib import Path
from healthcare_quality.ai_studio import ExperimentStore

store = ExperimentStore(Path(".local/v81-new-demo/expectations-v81.sqlite"))
for part in ("one", "two"):
    record = json.loads(Path(f"artifacts/v8.1/heldout-part-{part}.json").read_text())
    assert record["state"] == "completed" and record["approval"] is None
    record["replay_label"] = "Recorded actual local evaluation; no new inference or approval"
    store.create(record)
```

Refresh the saved-experiment list in the V8.1 panel, select a completed record, then refresh its status. Each saved batch contains five reserved inputs per model; `heldout-scorecard.json` combines the ten unique inputs. Historical results may be read on later code, but source/contract mismatch correctly blocks export. Never relabel a saved replay as a fresh model trial.
