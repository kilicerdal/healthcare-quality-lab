## Explicit live run

Expand Optional live AI, select a model/scenario and explicitly enter a budget from 1–300 seconds. No budget is preselected in V8.5. Click Estimate duration to see pricing and lifecycle estimates separately. Changing a selection or budget invalidates the estimate. A budget below the estimate can still be chosen, but may stop before both stages finish.

```sh
.venv/bin/python -m tools.expectations_v85 --models qwen3.5:27b --tasks D83-01 --max-seconds 180 --state .local/my-v85.sqlite --output artifacts/v8.5/my-first-attempt.json --dry-run
```

Dry-run creates no state and makes no provider/generation call. Use a fresh output filename. Remove `--dry-run` only for intentional inference. `--max-seconds` is required. The live command exits successfully only when all selected original trials are complete first-attempt passes, not merely because an HTTP request returned.

Each whole-case attempt has one pricing call and one lifecycle call, each once. Stepwise mode has one pair per requested step; optional blind review has its own pair and never replaces the original score. A strict original pass requires complete eligible original output and the expected un-reused stage sequence. Wrong values, invalid output, transport errors, timeouts, interruptions and unattempted cases remain separate. Resumed or retried passes never count as original first attempts.

For simple single-claim submit/pay/read/appeal scenarios, pricing may emit only one quote. Complex/cross-claim histories retain a safe broader bound because a later read can observe changed family balances. Lifecycle quote IDs are restricted to the model's actual pricing IDs. These are structural constraints, not precomputed expected numbers.

The budget begins at admission after separate bounded model preflight. Backend cancellation is best effort; late answers are fenced and the generation lock remains held until its worker returns. Do not overlap live inference programs on the same local backend.

## Sealed evaluation

```sh
.venv/bin/python -m tools.evaluate_first_attempts_v85 --prepare artifacts/v8.5/my-plan.json
.venv/bin/python -m tools.evaluate_first_attempts_v85 --plan artifacts/v8.5/my-plan.json --state .local/my-assessment.sqlite --output-dir artifacts/v8.5/my-assessment
```

Preparation writes input-only data and source/cohort hashes, without inference. The exercise selects the installed 27B model, one exposed pilot and three fresh numeric variants. It permits at most eight calls, 180 admitted seconds per case, and a 600-second admission window. A full case budget plus preflight headroom must remain before another case starts. Timeout/provider error stops subsequent cases to avoid adding work behind an uncertain backend operation. Not-run cases stay in the denominator; no completed fresh percentage is reported for an incomplete exercise.

The state and evidence paths must be fresh. The sealed plan must exactly match the implementation and cohort. Model digest/settings or source drift makes results incomparable rather than silently pooled. Never describe published H85 inputs as fresh in a future rerun.

## Reading the results

Use `evaluation-results.json` for all planned cases, individual trial JSON for raw prompts/responses and first-attempt classifications, and `progress.json` during a run. The current browser scorecard is derived without rewriting saved model predictions. Historical evidence is explicitly labeled and contributes no V8.5 first-attempt trials.

Calculators independently evaluate frozen answers after generation. They never provide or repair the model's expected values. V8.4's narrow unused-identical-alias normalization remains available; it changes no expected value. The one-quote V8.5 scenarios cannot emit those redundant aliases under their generation schema.

An eligible current-source export creates an unapproved proposal. Inspection/review and actual HTTP execution remain separate. A scripted engineering replay is not independent human review, and three fresh numeric variants are not broad model qualification.
