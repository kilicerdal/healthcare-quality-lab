# V8.2 operator and AI reliability guide

## Purpose

V8.2 tests whether less repeated output and more focused cap rules improve local model predictions. The model authors all financial quantities, pricing worksheets and lifecycle observations. A quote alias only copies values previously written by that same model. It never computes a missing answer, increments a counter or repairs an error.

The strict V8.2 gate requires complete correct observations and correct line worksheets for pricing actions. V8.1 additionally scored state worksheets; their strict scores are different measures. Observation correctness can be inspected separately, but different cohorts still do not make a matched before/after experiment.

## Start with development

Use D82-01 through D82-04. These are explicitly exposed V8.1 inputs targeting caps, mixed coverage, authorization and replay. They are not fresh evaluation evidence.

```sh
.venv/bin/python -m tools.expectations_v82 --models qwen3.5:27b --tasks D82-01 --state .local/my-v82.sqlite --output artifacts/v8.2/my-development.json --dry-run
```

Remove `--dry-run` only to make the explicit local request. Add `--strategy stepwise` to request one observation at a time, using only the model's own prior predictions. More requests can reduce per-request output but increase total wall time. Add `--self-review` only when deliberately testing blind review; V8.1 review recovered zero strict failures, so the dashboard defaults it off.

No automatic retries, model pulls, paid API calls or cloud fallback occur. The compact profile requests temperature0, seed7, maximum2600 output tokens, context12288 and timeout150 seconds. The larger installed model uses prompt JSON validation; the smaller model uses schema-constrained JSON. This is not an isolated model-size experiment. Requested seed settings are not proof that every backend implements deterministic execution.

## Understand compact quotes

Each response contains `quotes` and `observations`. A quote contains its own model-authored per-line `calculation` array followed by twelve financial/account/policy values. Each observation supplies a fixed step ID, a quote ID and six lifecycle fields. The parser copies the model's referenced values and worksheet into an expanded observation without arithmetic.

A changed account snapshot requires a new quote even when payout stays unchanged. Replaying a payment returns the old saved snapshot; a later read sees current state. A single fully rejected coverage line does not imply `partial=true`. That field means covered and rejected-coverage lines coexist in the claim.

Duplicate/unknown/unused quote IDs, wrong step IDs, reordered or missing steps, nonintegers and extra fields fail validation. Wrong pricing worksheets remain blocked even if the final API values happen to match. Private deliberation is not retained; requested numeric worksheets are retained and independently checked after output freezes.

## Read the dashboard

The V8.2 panel separates correct trials, wrong expected values, wrong pricing worksheets, invalid output, timeouts, other provider failures and unanswered stages. Failed/unavailable planned trials stay in the score denominator. Completed-response median latency excludes failed requests; request elapsed time is recorded separately, including timeout attempts. Refreshing saved results and loading the fault catalog make zero inference calls.

Raw evidence is collapsed by default so results remain readable on phones. All raw model text is rendered as text, never executable HTML. The controls stay disabled if configuration fails. Cancelling preserves partial evidence and fences late output.

Export independently rechecks a completed current-source answer, then creates an unapproved proposal. Inspect every financial/state assertion, review separately, and execute actual isolated HTTP. Exporting or replaying evidence does not become a new model trial. Code changes correctly make historical records ineligible for export.

## Six surviving pricing faults

V8.1's eligible AI cases detected21/27 production pricing mutants. The six survivors mutate allocation deltas or replace remaining-limit subtraction with addition of already-used balances. First claims with zero balances cannot distinguish those variants.

V8.2 adds six targeted authored multi-claim witnesses and an other-payer control. These are reference-calculated engineering tests, explicitly not AI-generated coverage. Reproduce:

```sh
.venv/bin/python -m tools.fault_audit_v82 --output artifacts/v8.2/my-fault-audit.json
```

This runs actual trusted production-code variants against healthy baselines, records witnesses and reduces each witness to a reproducible prefix. The dashboard reads a saved receipt and labels stale source rather than running mutations during page load. Actual AI-case detection must be scored separately.

## Evaluation discipline

The H82 cohort contains ten new input/amount combinations, including accumulated individual/family deductible, OOP and annual benefit use. Source, cohort, contract, model digest, settings, request budgets and selection must be locked before first model exposure. Freeze both original and optional blind review before independent scoring. Do not tune against published qualification answers and continue calling them reserved.

Repeated trials measure numeric observation consistency on the same inputs. They do not enlarge the ten unique scenarios or establish broad real-world reliability. All rules, members, identities and money are synthetic teaching fixtures, not actual benefit guidance.
