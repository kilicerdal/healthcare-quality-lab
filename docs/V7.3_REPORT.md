# V7.3 — Broader frozen AI evaluation

## Purpose and location

The earlier four-row result was too small to support a model ranking. We need more scenario variety, family-separated inputs and repeated trials while preserving raw failures.

All implementation belongs to the existing standalone project at `/Users/erdalkilic/Documents/Healthcare Quality Lab`. No existing sibling project was modified and VS Code was not opened. This is a milestone in one combined V8 delivery, not a separately deployed application.

## What was built and how

### Engineering decision 1

The new deterministic cohort has 31 authored input plans: 24 coverage boundaries across eight plan families and seven lifecycle journeys. Twelve commercial-PPO, Part-B, dental and vision boundary inputs are development; the other 19 inputs are locally reserved until exposed.

### Engineering decision 2

Development and reserved families are disjoint. These locally authored teaching inputs are not a claim of globally unseen model-training data. An actual request consumes exposure recorded in the experiment ledger.

### Engineering decision 3

The durable ExperimentLab now accepts an injected frozen cohort while preserving its original default. Protocols retain source, contract, cohort, prompt hashes, model digests, settings, token counts, latency, raw responses and repeated semantic stability. Cancellation, heartbeat recovery and fencing remain in force.

### Engineering decision 4

The CLI has a dry-run request budget, allowlisted models/prompts, one-to-three correlated repeats and a 24-request batch limit. Raw AI expectations receive one request with zero correction. Calculator rows make no inference call and are explicitly excluded from AI-reasoning metrics.

## Code and review map

Primary implementation and evidence entry points: `healthcare_quality/evaluation_v8.py; healthcare_quality/experiment_lab.py; tools/v8_evaluate.py`. Related behavior is exercised by the V8 unit/API/browser controls and the connected disposable rehearsal.

## Why these choices

The implementation extends the existing DSL, independent reference, persistence and review gates instead of creating another incompatible framework. It keeps deterministic engineering checks usable without a model and retains original AI outputs. Explicit authorship, source fingerprints and separate review prevent a successful job or attractive screen from being mistaken for a correct model answer.
